# Mainflix Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Implement the complete private four-person movie API, ready for local use and Vercel/Neon configuration.

**Architecture:** Express controllers call focused services using typed Kysely repositories. Database transactions serialize round mutations and admin eligibility changes; opaque cookie sessions use PostgreSQL too.

**Tech Stack:** Node 22+, TypeScript, Express 5, Kysely, pg, Zod, Node crypto scrypt; node:test through tsx and real PostgreSQL integration tests.

**Spec:** `docs/superpowers/specs/2026-11-09-mainflix-design.md`

## Global Constraints

- Four provisioned accounts; no public registration, email, Redis, or paid resources.
- Europe/Madrid Monday boundaries; weighted nominations; one immutable saved winner.
- API error codes support future Spanish/English JSON translations.
- Separate React/Vite frontend app included per the user update; Minecraft/Netflix visuals and one JSON file per language.
- Class methods only, explicit types, lazy ContainerProps getters; separate models/repositories and knucklebones-style exceptions/database interfaces.
- Existing checkout has no commits; work in place, leave changes reviewable and uncommitted.

## Review Focus

- Concurrent draw and admin requests must preserve one winner and invalidate disallowed nominations.
- Requests across Monday/DST boundaries must not mutate an expired round.
- Password resets and changes must revoke sessions even under concurrent login/reset requests.
- Cookie mutations must reject cross-origin requests and unauthorized users.
- TMDB errors/duplicates must preserve local data and avoid exposing credentials.
